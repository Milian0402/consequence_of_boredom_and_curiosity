The first replay used workflow run 45679590298, benchmark revision `70bb4cafd282bdb15ad2274fa4303343e90cfc3c`. Its Intel Xeon 6975P-C job 139436385985 retained the direct peers and historical controls. The prior release failed two CTests before any of the five release executables were measured. The original x86 raw artifact is 15055006173, SHA-256 `18ff305261bf621dd74a41c362a6d8fa268aa41208dbdd0f6f96e475148f4738`. Arm job 139436385882 completed successfully on this same revision. Preserve both original host artifacts separately from the repeated measurements.

Both tests forced tiny crossovers to exercise Strassen workspace behavior. With native AVX2/FMA or AVX-512 enabled, the unmodified public dispatcher legitimately chose the zero-allocation small x86 kernel before Strassen on the 64-square and 128-square fixtures. The original assertions expected Strassen allocations at the public entry. Linux GCC 13 reproduced both failures at the same checks with native flags and Haswell flags. The separately called Strassen functions performed the expected workspace requests.

Release test commit `b218beff1eaf8fd606d0934405cdc1e28ecdfe15` updates precisely those two test sources. They check the actual small public path and exercise the forced Strassen path independently with the original accuracy, guard, allocation and fallback checks. Additional 256-square public cases exercise allocation failures above the small-kernel range. The test source inputs at both registered production revisions are byte-identical. The runner applies the same two-test change to each method's private copy after building its unmodified CMake archive. It forces a clean rebuild and requires the two archives to compare byte-for-byte before running the corrected CTest and Make suites. The method logs retain both archive hashes and all test results.

All registered product sources, providers, flags, timed entry points, matrix layouts, seeds and scores follow the original protocol. Each method now builds in an independent shell. A failed test excludes its method, leaves a failed status in the job and allows the other methods to finish.
