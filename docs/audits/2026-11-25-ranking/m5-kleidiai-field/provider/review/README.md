# KleidiAI FP32 kernel eligibility on Apple M5 Max

The two proposed FP32 implementations can run on this Mac. The elastic SME2 dispatcher uses full-precision input, accumulation and output. Its main M5 tile measures 32 × 32 FP32 elements. Upstream supplies 16 × 16, 16 × 32, 16 × 64, 32 × 16 and 64 × 16 FP32 tiles for the edges. The row-major API takes matrix dimensions and byte strides, packs both inputs and includes space for FP32 per-column bias. The benchmark's ordinary overwrite GEMM supplies zero bias. The other selected implementation exposes the earlier SME2 two-vector packed format through its own public API. KleidiAI also ships an earlier SME-only packed FP32 matrix kernel and raw-left-input Neon kernels. Counts and comparisons of the two tested implementations should name their SME2 interfaces. The ordinary M × N scope excludes the specialized single-row GEMV paths. [Legacy SME2 API](https://github.com/ARM-software/kleidiai/blob/ab3f4b24a75f0667a1af9ebfe27e94efa7ce97e1/kai/ukernels/matmul/matmul_clamp_f32_f32p_f32p/kai_matmul_clamp_f32_f32p2vlx1_f32p2vlx1biasf32_sme2_mopa.h) · [Full FP32 packed kernels](https://github.com/ARM-software/kleidiai/tree/ab3f4b24a75f0667a1af9ebfe27e94efa7ce97e1/kai/ukernels/matmul/matmul_clamp_f32_f32p_f32p)

macOS advertises SME, SME2, SME2.1 and SME FP32 on the M5 Max. An untimed executable successfully used FP32 FMOPA and observed a 64-byte streaming vector length. The same executable running the exact FP32 FMOP4A opcode from the SME2.1 quarter-tile kernel raised SIGILL and returned status 77. That dispatcher's upstream requirements include both SME2.1 and the separate SME_MOP4 capability. The upstream macOS detector marks SME_MOP4 unavailable. The newer optional quarter-tile implementation is therefore ineligible on this specific host. The stable source contains no SME3 FP32 matrix implementation. On Apple Silicon with Xcode command-line tools, compile `clang -O0 -Wall -Wextra -Werror -march=armv9.2-a+sme2 features.c -o features`. Run `./features sysctl`, `./features mopa` and `./features mop4` as separate processes. The instruction runs establish availability; they do not measure performance. The recorded results are in m5-features.txt and m5-instructions.txt.
