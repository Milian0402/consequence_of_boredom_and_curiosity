# Preregistered terminal SGEMM update experiment

The candidate changes the two-level rectangular path in b218beff1eaf8fd606d0934405cdc1e28ecdfe15. It asks a serial BLAS to update each final-level P3 and P4 destination in place, with alpha +1 or -1 and beta 1. All other products, including P7 shared by two destinations, retain the original schedule. This removes 14 separate merge passes across a two-level multiplication. It can also change rounding and the BLAS microkernel choice.

Compare three normal-executable methods on the same Intel Xeon 6975P-C, pinned to one CPU and one process thread. Use identical compiler/linker, sequential oneMKL LP64, aligned and two-level release flags for the two COB builds. Toggle only COB_ENABLE_SIGNED_WINOGRAD_LEAVES=1. Compare them to direct sequential oneMKL. Include oneMKL JIT as a separate stronger peer when its ordinary one-shot API qualifies. Print actual CPU, enabled route, library identity, build flags and signed call counts. Test the five panel rows in their registered order. The first two repeat known independent-peer losses; the other three were selected before this experiment was timed.

Use two independent input seeds 31048579 and 196173023, three counterbalanced warm rounds per seed, and distinct processes per method. Time the whole public call from prepared inputs, including workspace allocation, cleanup and recombination. Record first-call latency separately. Admissibility requires all four FP64 full-output fixtures (both random seeds, scaled and cancellation), max absolute error at most 0.002, unmodified inputs and output guards, evidence of one true thread, and exact route counters. Report each layout's median time, paired ratios, win count and signed residuals.
