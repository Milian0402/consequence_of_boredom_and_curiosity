# HK15 on scaled, biased and ordinary FP32 inputs

On an Apple M5 Max, the updated optional HK15 path produced all **266,354,000 exactly representable outputs** correctly. On a further **469,839,504 nonconstant outputs** across eight cropped layouts, its largest absolute error against FP64 was **0.001133** (rounded up). All passed the project's absolute tolerance of 0.002. Each result belongs to these tested inputs and hardware. FP32 spacing and dot-product conditioning limit absolute and relative accuracy for other inputs. [Production revision](https://github.com/Milian0402/consequence_of_boredom_and_curiosity/commit/85a007747ff54241f47c4754216e0a65748f2847) · [Machine-readable results](summary.json)

The implementation checks input magnitudes, the scale of each row and column, and the number of substantial terms in each A row and B column. It then measures directional similarity in a sample of the eligible inputs. It routes strongly correlated inputs through COB's classical kernel. Very widely scaled inputs use lossless power-of-two scaling where possible, or binary64 accumulation. The ordinary signed, well-scaled path retains the fifteen-product schedule. Sampling can miss an unusual subset of rows or columns. The full-input scale and support tests inspect every logical entry.

The originally issued HK15 returned **91,050,004 inexact outputs** on the 44 exact matrix cases. Of those, 45,335,829 exceeded 0.002 and 8,061,956 were nonfinite despite a finite exact answer. Testing an intermediate classifier that checked just the row and column maxima eliminated many errors, but 11,288,051 outputs still exceeded 0.002. Requiring substantial support in the reduction dimension fixed every one of these exact cases. The subsequent correlation test addresses a separate source of absolute error on dense biased inputs. The raw output also reports sign changes and large relative errors near zero on centered signed data. [Original discrepancy](../hk15-input-scale/README.md)

## Which method was faster

On two irregular layouts, four biased input families took **1.20–1.30× the originally issued kernel's throughput** with the new public path. The geometric mean of the eight speed ratios was **1.243×**. These are warmed complete calls on the same addresses, with eight observations per method, layout and fixture. For 2083 × 3037 × 3121 with row/column-dependent signs, the new call took 27.91 ms, the old call 34.10 ms, and forced single-thread Accelerate took 25.68 ms. COB's direct classical routine took 24.87 ms. The final guard and direct COB passed all outputs on this case. Accelerate exceeded the absolute threshold on 13,595 outputs. Across all fourteen shape/distribution combinations, its largest error was 0.003575. These are small relative errors at the scale of the large positive sums. [Comparison protocol](biased/timing-protocol.md) · [2083-row timings](biased/dispatch-2083.csv) · [2233-row timings](biased/dispatch-2233.csv)

On ordinary signed data, the final guard's throughput was **0.916×** the originally issued optional kernel across four fixed shapes. Shape ratios ranged from 0.908 to 0.921. The two labels for the identical original function differed by at most 1.4% in their per-shape median ratios. This misses the preregistered 0.95× average criterion. The support-only version was already at 0.918×. The accuracy checks have a measurable cost. This timing comparison requires all output bits and padding to match on these ordinary inputs. [Protocol](benchmark-protocol.md) · [All 144 calls](coherence-timings.csv)

A separate optimization combined the safety checks into one read of each ordinary input. It kept the same classification for every value through a sufficient test with an exact fallback. In 512 complete calls the modified classifier improved throughput by 1.5% on the four previous shapes and 2.0% on four fresh ones. It missed the 3% adoption threshold in both groups and remains a benchmark experiment. [Full reduction rules, differential tests and timing replay](certificate/README.md)

## Rank-one correction experiment

For biased inputs, an alternative retained the fifteen block products. It wrote A as a residual plus a rank-one matrix along a sign vector, multiplied the residual by B and added the low-rank correction in binary64. On positive 2083 × 3037 × 3121 data the maximum absolute error fell from 0.002628 to 0.000131. It still missed 42 outputs across the two independent-profile holdouts. The complete projected call took 50.20 ms on that positive case versus 32.30 ms for direct COB in the same experiment. The simpler classical route had the better overall result. Apply the research patch to the support-only revision to reproduce the alternative. ## Reproduce

Run `python3 -B replay.py` here to rebuild `summary.json` from the full set of recorded CSVs. The experiment used macOS 27.2.1, an Apple M5 Max, Apple clang 21.0.0 and OpenBLAS 0.3.34 configured for one thread. Enable `COB_ENABLE_HK15_RAGGED`, `COB_ENABLE_PORTABLE_STRASSEN` and `COB_ENABLE_RECURSIVE_STRASSEN` in CMake Release. The normal test suite and both public HK15 validators passed. Raw sources for the exact and continuous oracles, the timed callers and the single-thread Accelerate wrapper are included.

The continuous-input programs in each panel take M, N, K, the seed and a path to a shared library exporting `cob_sgemm_rowmajor`, or `openblas`. Link them against OpenBLAS for the DGEMM oracle and set `OPENBLAS_NUM_THREADS=1` and `OMP_NUM_THREADS=1`. Every output is compared to DGEMM on exact promotions of the FP32 inputs. Each fixture checks 31 scalar reference dots, original inputs and output padding. The power-of-two checker compares with a separately derived exactly representable answer. Its fourth argument is an output label and it links to the chosen library at build time. The comparator labelled classical is the same release build with the HK policy forced to `COB_HK15_CLASSICAL` for the eligible parent shape. The full verifier checks recorded method/shape/seed identities and matched orders in addition to recomputing all score totals.
