# Guard overhead on the M5 Max

Only ordinary, well-scaled dense data from fixed seeds on four pre-existing full-size shapes enter this comparison. All four exercise the HK path. Same A, B and C addresses for all calls, two distinct seeds per shape, three labels (two identical incumbent function pointers A/B, one modified implementation G), each of six permutations once per shape and seed. Timing is one public call with internal temporary allocations. Guarded and incumbent results on this panel must match bit-for-bit before and after every timed call, including row padding. Check 96 logical positions against FP64 per layout and seed. All numerical stress cases are excluded from this calculation.

Compare G to the geometric mean of A and B within a matched block; summarize the twelve ratios by geometry with the median, then take the equally weighted geometric mean. Also report A/B null ratios and each seed. A speed ratio below 0.95 on average or below 0.92 on any one shape counts as material overhead for this M5 build. Both published option states, archive checksums, native compiler flags and the full raw samples accompany the findings. No cross-CPU performance inference from these data.
