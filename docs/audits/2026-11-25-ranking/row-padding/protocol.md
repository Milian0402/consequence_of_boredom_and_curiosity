# Rounding the output row count for a single native BLAS call

Select the serial direct provider by CPUID vendor string once at startup. Intel uses the same oneMKL SGEMM plugin as the independent direct test. AMD uses the same AOCL SGEMM plugin. The matched forwarding control calls that plugin with the original matrix arguments.

For 24–96 rows, 1024–4096 columns, and reduction depth 96–384, with at least eight columns per output row, consider rounding the row count up to a multiple of eight. Only pad if it adds at least one row and at most one eighth of the original rows. Copy A to a 64-byte-aligned array with zero dummy rows. Use one ordinary provider SGEMM and a temporary C, both with 16-float-rounded row strides where applicable. Copy the logical C back. B is used in place. Time every per-call copy, allocation, free, dispatch and computation. If ineligible or allocation fails, forward the original arguments. The CPU selection and backend initialization are shared by both wrappers. This tests a possible way to amortize a native library's edge handling.

Use the standalone study's entire frozen panel and evidence requirements. Among the eight fresh cases report all six paired ratios by layout against both the matched forwarding control and the underlying direct provider. Count ties and forwarding cases explicitly and report all counterexamples. Advance only if at least two genuinely padded fresh layouts exceed 1.02× against both controls with at least five paired wins on each comparison, the genuinely padded cohort geometric mean exceeds 1.02× against both, and no padded case falls below 0.97× against either. Report the fastest independent library and project method separately. This vendor-assisted experiment has its own decision and does not affect admission of the standalone candidate.
